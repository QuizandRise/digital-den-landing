# 4. WorkforceDen Fairness Principles

| **Principle**                     | **Mandatory interpretation**                                                                                                     |
|-----------------------------------|----------------------------------------------------------------------------------------------------------------------------------|
| P1. Explainability                | Material decisions must include a reason category, policy basis, impact, available remedy and appeal route.                      |
| P2. Proportionality               | The system must use the least restrictive intervention that adequately controls the risk.                                        |
| P3. Separation of concerns        | Account restrictions, project access, file access, payment holds and dispute actions must be separately controlled.              |
| P4. Human review                  | High-impact decisions involving identity, livelihood, money or permanent access must be reviewable by an authorised person.      |
| P5. Evidence before enforcement   | A report or automated flag is a trigger for assessment, not proof of wrongdoing.                                                 |
| P6. Role-appropriate transparency | Each user sees all information needed to understand their own position, but not internal margins or another user’s private data. |
| P7. Accessibility by default      | Accessible interaction is a product requirement, not a later accommodation.                                                      |
| P8. Data portability              | Users retain appropriate access to contracts, invoices, purchased deliverables and lawful account records after closure.         |
| P9. Predictable fees              | Fees must be shown before acceptance and locked for the agreed contract version unless both parties accept a change.             |
| P10. Auditable operations         | Sensitive decisions and state changes must produce an immutable audit trail.                                                     |
| P11. Progressive verification     | Verification must be introduced only at the point where the relevant capability, risk or legal duty arises.                      |
| P12. Data minimisation            | Personal data must be adequate, relevant and limited to what is necessary for a documented purpose.                              |
| P13. Equal treatment              | Nationality, immigration history, disability or another protected characteristic must not be used as a proxy for fraud or quality. |

# 5. Verified Marketplace Model

## 5.1 Proportionate onboarding policy

WorkforceDen shall apply **role-based, stage-based and risk-based onboarding**. Account creation must remain accessible and low-friction. Enhanced checks must occur only before the capability that requires them is enabled.

The platform must not collect identity, immigration, tax, criminal-record or professional-licensing information merely because it might become useful later. Collection requires a documented purpose connected to one or more of the following:

- legal or regulatory compliance;
- digital-platform tax reporting;
- payment or payout processing;
- service eligibility or regulated work;
- safeguarding;
- proportionate fraud prevention;
- insurance;
- access to a client’s private location; or
- another approved and recorded risk requirement.

The current UK legal position and WorkforceDen’s operating model must be reviewed before production activation. This framework is a product-governance requirement and does not replace legal advice.

## 5.2 Capability gates

| **Stage or capability** | **Minimum proportionate requirement** |
|---|---|
| Create a Client account | Name, verified email, secure authentication, Terms and Privacy acceptance. |
| Search or create a preliminary brief | No identity-document, immigration, tax or criminal-record check by default. |
| Enter a paid or local-service booking | Risk-appropriate phone, payment and contact verification. Full address is collected only when required for fulfilment. |
| Create a Professional account | Verified email, secure authentication and basic private/public profile separation. |
| Draft a Professional profile | Skills, services, languages, experience and portfolio; no public publication yet. |
| Publish a verified Professional profile | Identity and service-eligibility checks appropriate to the service, jurisdiction and risk. |
| Receive money | Payout onboarding and the tax/seller information required for the platform’s actual legal reporting duties. |
| Accept regulated or higher-risk work | Only the relevant licence, registration, insurance, safeguarding or eligibility evidence. |
| Access a Client’s full private address | Accepted booking/contract, current assignment and logged role-based access. |
| Perform eligible work involving children or vulnerable adults | Appropriate safeguarding process and only the legally eligible DBS level; not a universal DBS requirement. |

Verification must be progressive. A person may create and maintain an account without automatically receiving every marketplace capability.

## 5.3 Professional entry

1. Create a permanent account and verify email.
2. Complete a basic private profile and choose intended services.
3. Provide skills, services, languages, work history and portfolio.
4. Complete only the identity, seller-tax, payout, service-eligibility or safeguarding checks required for the capability being requested.
5. Undergo manager review before a verified public profile is published.
6. Choose availability, service mode and capacity.
7. Publish only approved public-profile information.
8. Retain correction, resubmission and human-review rights when verification is incomplete or adverse.

A failed automated check must not by itself produce a permanent ban. The system must distinguish `information_required`, `verification_pending`, `correction_required`, `approved`, `restricted` and `rejected` states and provide an appropriate remedy.

## 5.4 Client entry

1. Create a permanent personal or business account.
2. Verify email and accept Terms and Privacy information.
3. Complete additional contact, payment or identity checks only when the transaction, local-service risk or fraud signal justifies them.
4. Search professionals and teams or submit a matching request.
5. Negotiate through the platform and formalise the agreement as an Offer.
6. Accept the Offer and fund the project before delivery begins where required.

Client account creation must not routinely require passport data, date of birth, National Insurance number, immigration evidence, criminal-record information or a full residential address.

## 5.5 UK right-to-work and employment-status boundary

WorkforceDen must not automatically apply an employer-style Right to Work process to every independent Professional merely because they use the marketplace. The applicable duty depends on the real legal relationship and operating model, not only the label used in Terms or a profile.

Before any workflow treats a Professional as self-employed, worker, employee, contractor or agency worker, Product and Legal must assess the actual degree of control, substitution, personal service, mutual obligations and other relevant facts. Where the relationship or service model creates an employer or engager duty, the correct UK process must be followed.

The platform may request work-authorisation or eligibility evidence where it is genuinely required by law, contract, safeguarding, insurance or the regulated nature of the service. It must record the purpose, lawful basis, access controls, retention period and review route.

## 5.6 Digital-platform seller reporting boundary

WorkforceDen’s marketplace model is likely to fall within UK digital-platform reporting rules if it connects sellers to customers for services. Before Professionals receive reportable payments, the platform must determine whether Quiz & Rise Ltd is a reporting or excluded platform operator and implement the seller-information, verification, reporting and seller-copy duties that actually apply.

The product must support staged collection so that reportable seller data is not demanded from ordinary Clients or from Professionals before the relevant reporting/payment capability is enabled. Seller-tax data and payout data must remain private and role-restricted.

## 5.7 DBS, licences, insurance and regulated work

- DBS checks must be required only where the role is legally eligible and safeguarding risk justifies the relevant level.
- The availability of an Enhanced or barred-list route for eligible self-employed people does not make such checks universal.
- Trade licences, registrations and insurance must be category-specific. Examples may include regulated gas work, electrical certification where relevant, driving/vehicle insurance for transport, or public-liability cover for selected local services.
- WorkforceDen must show a public verification badge or service eligibility state, not the underlying sensitive document.
- Expiry, suspension and re-verification must be managed without exposing private evidence.

## 5.8 Verification fairness and reasonable adjustment

Verification and onboarding must:

- support correction and resubmission;
- provide a clear reason category without exposing fraud-detection secrets;
- offer human review for adverse or high-impact decisions;
- support reasonable adjustments and accessible alternatives;
- avoid penalising users because an automated document reader, facial check or form is inaccessible;
- work with keyboard navigation, screen readers and browser zoom/reflow;
- separate public profile content from restricted identity, tax, address and safeguarding information; and
- record who approved, rejected or restricted a capability and why.

## 5.9 Capacity-led service visibility

A service category should become searchable only when at least one approved professional or team has verified capability and active capacity. Categories with no current capacity should be hidden, marked unavailable, or offered through a managed matching request. WorkforceDen must not advertise supply it cannot reliably fulfil.

# 6. Search, Ranking and Discovery

## 6.1 Search result composition

- Individual professionals.
- Verified teams, including the Digital Den network.
- Relevant service categories generated from approved profiles.
- Availability, response expectations and service location/language filters.

## 6.2 Explainable ranking

Ranking must not be a black box. Professionals should see which controllable factors affect visibility. No single private signal should silently destroy visibility.

| **Permitted ranking factor** | **User-facing explanation**                                    |
|------------------------------|----------------------------------------------------------------|
| Verified skill match         | Your verified services match the client’s query.               |
| Profile completeness         | Complete profiles provide clearer information to clients.      |
| Availability and capacity    | Profiles marked available may rank above unavailable profiles. |
| Response reliability         | Consistent, timely responses improve service reliability.      |
| Delivery reliability         | On-time, accepted work supports trust.                         |
| Quality and satisfaction     | Multi-dimensional feedback contributes proportionately.        |
| Relevant experience          | Comparable completed projects may improve relevance.           |

## 6.3 Prohibited ranking practices

- Permanent or severe visibility reduction without an identifiable reason category.
- Pay-to-rank mechanisms that overpower relevance and verification.
- Using disputed or overturned moderation events as permanent negative signals.
- Using protected characteristics or close proxies as ranking factors.
- Allowing one anomalous review to dominate the score.
- Ranking users lower because they requested an accessibility adjustment or used an alternative verification route.
